Changelog¶

All notable changes to KOLONİ are listed here, newest first. English only.

[Unreleased]¶

Added¶

  • Chat: talk to the Orchestrator while its agents work. While a turn runs the message box has Send now (Enter) - "the Orchestrator reads it in this turn": your message goes into the turn at work, and the Orchestrator answers it then, from where it waits for its agents or at its next step - and After this turn, which queues it as before. The box says "Write to the Orchestrator - it reads it in this turn…". Where the turn takes no message (a plan turn, a comparison, a To-do task's or a night job's turn, one not started from your page, another topic) or was ending, the message is queued and the box says why under it ("Queued: the turn was ending"). A message is never lost or read twice: a turn stopped or failed before the Orchestrator read it puts it in a turn of its own. The steps that answer it change nothing themselves - no file, command, web request or MCP server's tool: new work goes to an agent - and do not wait for a place among its agents at work. What you send now is your own word: a push card quotes it as it quotes the message that started the turn, the newest deciding (docs).
  • Agents: Stop and Message on an agent at work - on its node on the canvas and in its window's head - for one an agent opened. Stop ends that agent alone: the chat says "You stopped Coder. Its work so far is kept for your Take in; nothing of it is in the project.", the Orchestrator is told not to open it again unless you ask, and the rest of the turn goes on. Message opens its window at its Tell box. KOLONİ's own checks and a team recipe's agents keep their own Stop (docs).
  • Agents: the Orchestrator of an API model can open an agent in the background: it goes on at once - talks to you, opens others, messages or stops it with its new stop_agent - and takes a step for each agent's report as it comes, saying an agent is still at work until then. It can run a command in the background too (run_command with background), read it with command_output, stop it with stop_command, and is told when it ends. The chat's limits hold them as any agent (docs).
  • Agents: the Orchestrator of an API model says how a message to one of its agents goes (message_agent's how): reply as ever; leave - it goes on, an agent not at work takes it up now in a turn of its own, one at work is handed it at its next step or takes it up once its work ends, and the reply comes as a note; now - into an agent's running work (a CLI's running turn, with what came of it), else as leave. Only to agents it could message anyway; such a turn waits for the agent's other turns and for a place; a message left counts twice toward the turn's messages between agents; and however it ends - read, replied, the agent stopped, the turn over - the Orchestrator is told (docs).
  • Agents: reading a command that keeps running (a dev server, a background command), an agent can first wait for a piece of text to be printed - "listening on", "passed" - up to 2 minutes (command_output's until and timeout_seconds), told the line it was seen in, that it was not seen in time, or that the command ended; no step is spent on each look. A piece of text, not a pattern, looked for only in what the agent may read (secrets hidden) (docs).
  • Notifications: when an agent nobody waited for ends while nobody looks at its chat, a desktop notice says so - "Reviewer finished: 2 findings", "Coder stopped" - where the project has Desktop notifications on; it holds only the agent's name and how it ended. "Nobody looks" is herdr's rule: no page has the chat on screen with its tab seen and its window in front - a hidden tab, another window or another page of KOLONİ's over the chat is nobody; the notice that a card or a question waits for you now follows the same rule, and is no longer shown while you look at the chat (docs).
  • Notifications: desktop notifications on macOS (terminal-notifier where it is installed, else the system's own) and on a Linux desktop (notify-send) - before, Windows only; the words go to the program as arguments of their own, never through a shell. Where neither the program nor a desktop is there, the switch stays greyed out (docs).
  • Chats: a chat whose last turn ended - done, stuck or stopped - while you were not looking at it says so: "Done · not seen" on its row, and in Now, which puts what waits for your word first, then what ended where you have not looked since, then what is at work (herdr's order). Opening the chat, or a turn of it ending while it is on screen in front of you, makes it seen; a desktop notice does not. Every chat there was when KOLONİ upgrades the database counts as seen (docs).
  • Chat: a line over the chat while its turn runs with agents at work, a plan of the Orchestrator's or something waiting for you - "3 agents at work · step 3 of 6 · 1 waits for you · ≈ 0.40 USD": who is at work below the Orchestrator, the step of its plan, the cards that wait for you, and what the turn cost so far at your prices (left out where nothing of it is priced, never a made-up zero). A click opens At work in this turn: each agent, "Coder · working · since 14:02", with its Stop and Message, the Orchestrator's plan, and Open Ready for you (docs).
  • Agents: while its agents work the Orchestrator reads who of them is at work, since when and what each last said (agents_at_work, its words quoted and masked), and an API model's Orchestrator shows you its plan (update_plan): its window says it under Plan (its own words) - a Codex Orchestrator's plan too - and the line over the chat says its step. The plan goes with the turn (docs).
  • Agents: the Orchestrator can ask a second model for advice on a hard choice (ask_advisor), at most 3 times a turn: your new Advisor model in Settings › The app › Agents ("A model the Orchestrator may ask for advice. It sees the Orchestrator's summary and the turn's recent steps, masked."), else a model on another provider than the Orchestrator's, the strongest first - only one that answers with its tools off. It is sent the Orchestrator's question, summary, last 12 steps and who is at work, masked, and no tools; its answer comes back as data. Where none can be asked, the Orchestrator is told why and goes on. Its request is in the turn's spend and on Usage under its model (docs).
  • Ready: a decision the Orchestrator took for you without asking it can note (note_decision): a row of Decided for you, "Orchestrator · Decided: "Use SQLite for the cart"" with its reason, new until your OK, at most 10 a turn. Change takes your own words: into that turn while it works, as your message, else a turn of KOLONİ's in its chat tells the Orchestrator. When the database is upgraded (migration 0197) it gets a table for them; nothing else changes (docs).
  • Agents: the Orchestrator reads one pull request of the project's GitHub repository (read_pr_feedback, by its number or address): the review decision, the checks that failed or have not ended, each review and comment and the comments on lines, with who wrote each - with your own gh, read only, where it is installed and the project's origin is on GitHub. What reviewers and checks say comes as data, masked and cut, and where it reads like orders to an agent the chat warns you, as for a web page (docs).
  • Agents: a role with Run inside the CLI also runs inside GitHub Copilot CLI run Native (Copilot 1.0.114 on, its provider in the team guide): the Copilot Orchestrator is given the roles you turned on as sub-agents of its own, none of Copilot's built-in ones, and opens one with its own task tool. It is shown as an own sub-agent, "Checker (inside GitHub Copilot CLI)", with what it did inside it, and runs on the Orchestrator's model (docs).
  • Memory: when you say how you want work done from now on ("from now on don't ask me for X", "write commits in Turkish"), the Orchestrator keeps it for Your preferences, from your own words only - it quotes your sentence of the turn and KOLONİ checks it is a sentence of your own prose, never a fenced, quoted or backticked line you pasted, an agent's words or a tool's. As your new setting New preferences from your words says (Settings › The app › Agents): Add them, tell me (the default) adds your own sentence at once - never the model's wording, and only a plain rule: one that asks, forbids, sets a condition, takes back, names a push, a pull request or a merge, or reads as a request for this work goes to the card - and the chat says "Added to your preferences: "…"" with Undo; Ask me first puts the Orchestrator's line on a card under your words, with Add and Not now. Masked, cut at 300 characters, at most 3 a turn, never twice the same line (docs).
  • Agents: the Orchestrator's agents_at_work says what each agent waits for - a card of yours (its command or change, named), an answer to its question, its command running and since when, another agent, a place at its provider or in the turn - read from KOLONİ's records alone, "unknown" where they say nothing; At work in this turn over the chat says it beside each agent (docs).

Changed¶

  • Settings: a line of Your preferences never lets Full auto's check of your words run a command without its card - your words in the chat or the project's rules still can; a preference that forbids a command still stops it (docs).
  • Settings: of your messages, Full auto's check of your words runs a push, a pull request or a merge only on that turn's - the one that started it and those you sent into it; a sentence of an earlier turn never runs one (it can still stop one), so "You can push to main from now on." lets no later turn push (docs).
  • Permissions: at Full auto, in a chat you watch with the judge on, a plain push of the branch you have checked out to its own origin - git push, git push origin, git push origin <branch>, git push -u origin <branch>, git push origin HEAD - goes to Full auto's judge instead of a card, as Claude Code's auto mode: its fine pushes; its risky is the push card the list gave before, with the judge's reason on it ("KOLONİ's judge: …") - never a refusal, nor counted among the judge's refusals - which quotes you where you asked for the push. A push to main, master or origin's default branch stays a card at every level (quoted where you asked for it), and so does any other push - forced, tags, another branch, ref or remote -, every push at Ask and Auto-edit, in a To-do task's turn or a job while you're away, and where no judge model answers (docs).
  • CLIs: GitHub Copilot CLI run Native hears your word while it works: its Tell box is there again, and Send now goes into a Copilot Orchestrator's running turn (measured with Copilot 1.0.114). An agy agent's box says it can't hear messages while it works and sends your words to the Orchestrator instead (docs).
  • CLIs: a word written into a CLI's running turn - Send now, an agent's Tell box, another agent's message - comes to one of three ends, read from the CLI's own sign (measured on 27 Nov 2026): taken (Claude Code echoes it before its result, Codex answers with its turn, Copilot names it as taken before it goes idle), not sent (its turn was over - Codex's "no active turn to steer" - or it could not be written: Send now is read at the Orchestrator's next step or run, as before; a Tell or a message Codex said no to only after 5 seconds waits for the agent's next step, and a Tell's is said in the chat) or unknown (written, and no sign by its turn's end, or a no not measured) - never sent again, since it may have been read, and said in the chat: "Lead may not have read your word before its turn ended: … - it is not sent again; say it once more if it still matters". A Change of a decision or an answer still stands and is given again. An agent that sent the message is told which, in its answer or in a note. Claude Code 2.1.332 or later is started with --replay-user-messages for it, and a run whose word it echoed in its turn ends at its result, without the 30 seconds' wait for a turn on it (docs).
  • Settings: Full auto's judge reads new words ("D2"): what your words ask for is fine as far as you named it - never another target or more, never emptying or overwriting a file that was there; a plain push of the branch being worked on to its own origin is ordinary work; work your words do not ask for that reaches outside the task (an outside service, CI or settings files, another repository) is risky; and so is what Claude Code's auto mode blocks - amending a pushed commit, --no-verify, --insecure, an agent loop with no sandbox. Measured on 28 Nov 2026 on 252 cases with Claude Code's haiku: every ordinary command fine, 99% of the risky ones risky, 2.6 seconds at the median; it still lets an empty of a file by now and then, and called some empties you asked for risky (docs).

Fixed¶

  • Chat: a command kept off its Always run rule by an agent's write of a file it may read - an .npmrc or x.npmrc, a package.json, a lock, a tsconfig.json, a pyproject.toml - says so on its card: "an agent wrote a file this line may read or load (evil096.npmrc)"; it said "an agent wrote its program" of a file the line does not run. Where an agent wrote the program too, the card names the program, whichever was written first. The rule still stops there, and no rule is offered (docs).
  • Docs: Codex run Native asks KOLONİ before its commands, a read of .env too - measured with Codex 0.172.0 on 27 Nov 2026; the guide said it ran its own safe commands (a .env read among them) unasked; older versions were not measured again. A command an allow rule of Codex's own covers still runs unasked and is recorded after it ran; the Models page and a Codex agent's window now say just that, no longer that its reads of secret files or of files outside the project run unasked (docs).
  • Permissions: a search with a quoted ;, &, &&, | or bracket that names .github (rg '&&' .github/workflows, rg 'a|b' .github) runs at Full auto as a search does: it was a card, "Names .github: … asked at every level", as its parts were cut inside the quotes and .github/workflows read as a command of its own. A line any other program runs keeps its quoted ; a cut - ssh host 'cd app && rm -rf build' is still a delete -, and so does a line handed to a shell, such as cmd /c "…", which keeps no ' quote. A search told ag's or ack's --pager by --pag, or ack's --output (Perl to ack 2.x), is no search: ag --pag='sh -c x' foo .github names .github (docs).
  • Chat: the line at a chat's top no longer starts "While you were away," - the Orchestrator notes a decision in a turn you watch too: "1 thing was decided for you in this project and 1 waits for you here." (docs).
  • Chat: going away from a chat whose Orchestrator is GitHub Copilot CLI run Native, the Go away line names and takes the tasks the Orchestrator itself put on To-do in that turn, as with Claude Code - it named none ("Tick the tasks to take in Change"); a task one of Copilot's own sub-agents tries to add is refused, as all KOLONİ's tools are to them (docs).
  • Memory: the hint by a suggested preference on the Memory page said nothing enters your preferences unless you add it - at New preferences from your words: Add them, tell me the Orchestrator adds a plain rule of yours itself. It now says that a suggestion, the summariser's or the Orchestrator's from your own words, enters only when you add it, and that at Add them, tell me the Orchestrator adds a plain rule itself, with Undo in its chat (docs).

Security¶

  • Permissions: writing the files Claude Code protects that KOLONİ did not asks at every level now, Full auto too, and one written unasked is put back: .devcontainer/ and .devcontainer.json, .gitmodules, .cargo/, .mvn/, Gradle's wrapper (gradle-wrapper.properties, gradle-wrapper.jar), .bazelrc and .bazelversion - each runs or fetches code by itself, when the folder is opened or at the next build; .idea/ asks too, but is not put back (a JetBrains IDE rewrites it itself). An approved git submodule add, set-url or set-branch may write .gitmodules; ./gradlew test and cargo test run as before (docs).
  • Permissions: lines Claude Code still asks of are no search or look to KOLONİ either: a wildcard that may expand to an option (find *, rg foo *, cat -* - a file named -delete or --pre=x in the folder would be one) and a search chained to another command; and a redirection to bash's /dev/tcp/ or /dev/udp/ - or to a /dev/ path the shell builds as it runs (/dev/$t/h/80) - reaches the internet: asked at every level while a web tool is off. A ;, & or | inside quotes chains nothing in a search on a simple line (rg '&&' .github, rg 'a|b' .github: no backslash, backtick, $, #, line break or typographic quote, where sh and PowerShell read the quotes alike); in any other line, or any other program's, it is a card (docs).
  • Permissions: at Full auto, git run in a folder below the project's root (git status there, as cd sub && git status), in a folder KOLONİ does not know (Claude Code's PowerShell), or at a root with no .git but a HEAD (git may take it for a repository of its own) is put to Full auto's judge instead of running as a read or as ordinary work: a repository shaped there can set programs git runs. Below Full auto, such a root's git read is a card (docs).
  • Permissions: an approved git submodule foreach … (or status, or any other line that only names a submodule) no longer lets a change to .git/config stand after it - the command it runs could set a program git runs (core.fsmonitor); only the git submodule verbs that write git's config do, and a chain with a git command that runs one it is handed in it - git submodule foreach, git rebase -x, git bisect run, git difftool -x, git grep -O, git filter-branch - lets nothing stand (docs).
  • CLIs: Codex no longer opens sub-agents of its own. Codex 0.172.0 opened one when asked though KOLONİ switched its multi_agent feature off (measured 27 Nov 2026, gpt-6-luna); KOLONİ now also sets agents.enabled=false, with which it had no such tool (measured with its app-server, which Native and the session use; step by step and its web search are given the same switch, not measured there).
  • Permissions: a push of your feature branch reaches Full auto's judge only where KOLONİ finds nothing that sends it elsewhere or sends more: origin's default branch as origin itself names it (an origin that names none is a card), git's settings (no remote.origin.url, the branch's upstream or remote, push.default=matching, a push map, a mirror, tags, push options, a receive-pack, submodules - submodule.recurse too -, a hook set in the settings, a settings file git reads from the project out of .git - an include.path to ../.gitconfig an agent may write), a project that runs its commands in Docker, a branch or commit that moved between the judge's fine and the run, origin's address or git's settings changed since the turn began (an agent's git remote set-url), a pre-push or reference-transaction hook at all (yours too: husky's, Git LFS's - an unchanged hook can run what an agent wrote), origin a folder in the project, or a secret KOLONİ knows in any commit the push sends - counted against what origin itself says it holds, never a branch git keeps of origin's here. Each is a card. A judge's fine on a push lifts nothing once the judge is turned off while it looks (docs).
  • Permissions: a git remote that changes origin - add, set-url, remove, rename, set-head, set-branches, whatever the case of git's words and however the name is spelt (a quote inside it: ori''gin) - is asked at every level, Full auto too, as setting git's settings is: an origin an agent changed in one turn was the next turn's origin, unseen. Another remote's (git remote add upstream …) runs as before (docs).
  • Workspace: a secret in a root commit - an orphan branch's first commit, or the first commit of a history merged in - is found where KOLONİ looks through a branch's commits before it keeps or pushes one; a root commit's files were not read (docs).
  • Agents: a role run inside GitHub Copilot CLI is held as one inside Claude Code: each of its tools is asked through KOLONİ, held to its role's own tools, with a card where your level says so - at Ask a role that can change things is a card before it opens, as opening an agent is; it may not use KOLONİ's tools (the Orchestrator's, over the bridge Copilot shares with it), open a sub-agent of its own, or delete a file unless its role runs commands; Copilot's task opens only a role KOLONİ gave it, while the Orchestrator waits for it, and never with a model, level or setting of Copilot's choosing; a sub-agent KOLONİ did not open may use nothing; where its commands run is taken as not known (Copilot does not run them where KOLONİ puts the Orchestrator's), so its git reads ask at Ask and its git lines go to the judge at Full auto; and one of its tools that ran without KOLONİ being asked stops the turn. Its words, context and model are never the Orchestrator's - they no longer count a word you sent now as read -, and its tokens are counted in the turn (docs).

[0.1.10] - 2026-11-27¶

Changed¶

  • Ready: Ready for you and To-do are one page, Work - the rail's Ready is named so, and its To-do is gone. Work has two tabs under its heading, each with its count - Ready for you ("Ready for you · 2", what waits for your word) and To-do (its tasks not done) -; it opens on the tab shown last while KOLONİ is open, the arrow keys go from one to the other, and what you type on one, or a story open on To-do, stays as you switch. On Ready for you, what was done: a greeting, then the report of the project's last ☾ Away, while it works and once it has ended - one sentence ("2 of 3 jobs done, 1 could not be done."), a row for each job with its branch, checks and Take in / Try again / Open its chat, the night's lanes, how many were decided for you on its jobs and not seen (See them), what it spent, Copy report as Markdown - or one line, "Nothing new since you last looked", with no night or one seen and over a day old. Under it Waiting for your word, one list in one frame, each row saying what it is - Push, Parked command, Question, Proposed task, Done?, Ready to take in… - and whose; and Decided for you, a row you have not seen marked new. Ctrl+K's Work › To-do, a chat's Open it in To-do, The task on a decision and the canvas's To-do → open the To-do tab; the morning after a night, the top bar's ☾ Away line, Open in Ready for you, Ctrl+K's Work › Ready for you ("ready" finds it) and the top bar's pill on Work open Ready for you (docs).
  • To-do: each story is a card - its name, how many of its tasks are done, a honeycomb cell for each task and its tasks with how each stands (done, at work, done?, push waits for you, stuck, queued…) - and the tasks of no story one more card. A card opens its story in a panel over To-do: its branch where a night's job had one, its chat and state, its notebook with who wrote each note and when, Continue in chat, ☾ Do tonight (the Away panel with its tasks ticked), Close story (or Open it again), Rename and Delete, and its tasks with all they did - tick, order, edit, waits for, delete, their notebook and chat - and Do in chat. Close or Esc shuts it; while it is open what it lies over cannot be reached, and on a narrow screen it is a dialog over the whole page. The rough note is always in sight under the cards, its button Split into tasks. A proposed task's buttons say what they do: Add to To-do, Edit, Not wanted. What waits for your word on To-do - a proposal, a "done?", a change - is in Ready for you's one list, not twice on the page; a task the Orchestrator added at Full auto waits for your OK under Decided for you (docs).
  • Ready: a small hexagon - a cell - says how a thing stands, the same on the report, in Waiting for your word and on To-do: green done, honey at work, a honey rim your word, red-orange stuck, empty queued, a thin rim proposed. A word or its name always says it too, never its colour alone (docs).
  • Chats: the Chats page speaks in the same cells. Each chat has its cell and one line under its name: what waits for your word in it and what (a command, a question, a file change…), who is at work and on which branch, stuck (its last turn failed or was interrupted, or its To-do task is blocked), done with what it ran on, stopped, or no turn yet; a chat not read yet says nothing. What waits in a chat is what Ready for you lists for it, the top bar's pill's count. On top, Now over every folder, one strip across the page that stays in sight while the list scrolls under it (on a narrow window it wraps and scrolls away): a cell for each chat at work, each thing that waits for your word and each chat stuck or done today, one sentence that counts them, Go to Ready for you and what the cells mean; the list takes the page's whole width under it. Search, the state and sort choices, New chat and From a GitHub issue… are one row beside the heading. Each folder says how many chats it holds; the page's heading is Chats, as the rail says (docs).
  • Tools: the Tools page speaks in the cells too: a tool's or a server's cell says how it is let run - green runs without asking, a honey rim asks you first, empty is off, red-orange a server whose trust a reading took back - with their key under the heading.   • Models: with a model server that is not running, KOLONİ's check of it takes about half as long (on Windows about 2 seconds instead of 4): a server that takes no connection is asked once, not twice.

Security¶

  • Install: KOLONİ listens on 127.0.0.1 only and sends no telemetry; every request to its API needs the page key, so a plain or injected command an agent runs cannot approve its own cards (docs).
  • Install: exports and backups are downloaded without the page key in their address, so it stays out of your browser's history.
  • Settings: an export without keys also leaves out secret files you attached to a chat (a .env, a key file); the chat keeps their name (docs).
  • Install: a link with a wrong key, from a web page or an agent's answer, no longer locks the page out: the page keeps its key unless KOLONİ accepts the new one, and links in agents' answers and diagrams open in a new tab.
  • Ready: reading secret files, writing most files that steer agents, and commands that delete or send data off the machine stop at a card at every level, with a few exceptions for CLIs run with their own tools (limits); at Full auto these checks are for honest commands, not a wall (docs).
  • Ready: a command an agent runs is judged together with the folder it runs in, so a relative path inside .claude or another protected folder stops at a card as if it were named; Claude Code and Qoder don't say where their shell stands, so their commands are judged at the project root (a cd into a protected folder is itself a card).
  • Ready: KOLONİ's own cards have fixed titles and say KOLONİ asks; an agent's question says The agent asks, so it cannot pass for one of KOLONİ's.
  • Workspace: sub-agents work in working copies, not in your folder, until you take their work in.
  • Agents: your home folder and a drive's root cannot be a project, and KOLONİ's own folder is never opened, even inside a project; a CLI's own Grep and Glob cannot search it either (docs).
  • Agents: web pages, search results, MCP results, knowledge, a GitHub issue and a learned repository's code reach agents framed as data, not instructions; the frame tells the model, it is not a wall; text that tries to give orders shows a Text tried to give orders card (docs).
  • Settings: secret files open only on your Allow once and searches skip them (at Full auto a command that doesn't name the file can still read it); keys in command output show as ***; variables with secret names are kept from commands and CLIs unless you name them (docs).
  • Settings: a planted test key stops a command, web request, browser or MCP call that would send it out.
  • Chat: an agent asks for a key on a Give a secret to its commands? card; the value never reaches the model or the record, and never leaves on a branch (docs).
  • Triggers: turns nobody watches may do only what the trigger allows, and never start a CLI that works with its own tools (docs).
  • Tools: commands can run in a fresh Docker container, with the network off unless you allow it (docs).
  • Tools: MCP servers get only their own variables and what programs need to run, none of KOLONİ's or a CLI's sign-in; one you have not trusted asks before every call (docs).
  • Tools: web searches and requests reach only public addresses; the agents' browser opens only previews and the sites you allow.
  • CLIs: on Windows, a CLI and everything it starts run in a Windows job that is ended on Stop or when KOLONİ closes.
  • Docs: the guide at /guide/ loads its scripts, styles, fonts and pictures only from KOLONİ itself.
  • Docs: report a security problem privately through GitHub's Security tab (docs).

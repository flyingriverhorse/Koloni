Permission levels¶

The permission level decides what agents may do without asking you first. It stands in the message box's row as three comb cells and its name (Ask one cell, Auto-edit two, Full auto three): a click lists the levels, each with a line on what it does - Ask before changes: "Each file change and command waits for your card"; Auto-edit files: "Writes files at once (revertible); commands still ask"; Full auto: "Changes and commands run; only harmful or risky actions ask" - Plan first, and in a project's chat Test and review changes (what KOLONİ checks after a change, on or off for this chat; off, the level says "· no checks"). Each chat has its own level.

Level In short
Ask before changes Each file change and each command waits for your card.
Auto-edit files File changes are written at once and can be reverted. Commands still ask.
Full auto Changes and commands run without asking. Only harmful or risky actions still ask.

What asks at each level¶

"Card" means the agent stops and waits until you answer on a card in the chat. "Runs" means it goes ahead without asking.

A plain git command counts as read-only only when it runs at the top of the project and the project holds no secret file. As in Claude Code, these are no read either: a line that sets PATH or IFS, git after a change of folder (cd sub && git status: a repository shaped there can set programs git runs), a redirection to bash's /dev/tcp/ or /dev/udp/ (it reaches the internet), and a wildcard that may expand to an option (find *, rg foo *, cat -*: a file named -delete or --pre=x in the folder would be one; src/*.py and a quoted '*.py' are fine).

A search chained to another command is no read either. A ;, & or | inside quotes chains nothing in a search on a simple line - one with no backslash, backtick, $, #, line break or typographic quote, where sh and PowerShell read the quotes alike: rg '&&' .github/workflows and rg 'a|b' .github are searches, at Full auto too. In any other line, or in a line another program runs (ssh host 'cd app && rm -rf build', cmd /c "…", which keeps no ' quote), it is a cut, and what comes after it is judged as a command of its own.

The secret-file rows have exceptions for CLIs run with their own tools (a command Codex's own allow rules cover, agy's reads): see Known limits.

The folder's .koloni/¶

In .koloni/ A command naming it, or a write there
tmp/ - the agents' scratch Judged as any path: no card of .koloni's, at every level
worktrees/, copies/ - KOLONİ's worktrees and copies (where) A look - ls, cat, a search, the Files window - is judged as any; a write, a delete or a program run there is a card at every level
Everything else: rules.md, settings.json, recipes/, knowledge/, the teams' shared/ folder Card at every level, Full auto too
  • Each worktree and copy is one agent's work. That agent works in it as its own folder - by its full path too (cd C:/…/.koloni/worktrees/<id>/<agent>/tree, Git Bash's /c/…) - with no card of .koloni's; any other agent, or a command at the project's root, only reads there. A write, a tee, cp or mv into one, a file tool's write (also at Auto-edit and Full auto), a delete, a program run from one, or pytest's --basetemp there is asked at every level.
  • A search is a look only while it only reads. Its options are read as the shell joins them, so a quote or a backslash inside one changes nothing: find src -de""lete is a delete, and -fpr""intf, -ex""ec, rg's --p""re= and --hostname-bin, ag's and ack's --pager (or --pag), and ack's --output (Perl to ack 2.x) make it no read. A find word in bash's ANSI-C quotes ($'-de\x6cete'), which KOLONİ does not decode, is taken for a delete, and ag or ack is no look into a tree. In a worktree or a copy such a line is asked at every level.
  • What is inside the scratch is still judged as any path: a .claude/settings.json there asks as it does anywhere, and a git line that names a free folder (git add -f .koloni/tmp/x) asks.
  • A line that climbs from a free folder into the rest - cat .koloni/tmp/../rules.md, cd .koloni/worktrees; echo x > ../rules.md, a path built from where it stands - asks at every level, its card saying "Climbs out of .koloni/tmp…".
  • A delete is a card at Ask and Auto-edit as any delete is; at Full auto a plain delete inside tmp/ runs with no card - inside worktrees/ or copies/ it is a card.
  • The teams' shared/ folder is not free: who writes where there is the teams' own rule (write_shared writes a team's folder only, and each file says who wrote it); agents read and write it with their read_shared and write_shared tools.

The cards¶

An agent asks, you approve: Run once on its card, and the turn goes on.

  • A file change shows the diff, with Approve and Reject. After it is written you can still Revert it.
  • "Run this command?" offers Run once, Always run … and Reject. Always run keeps a rule for this chat, so the same kind of command runs without a card next time. Some commands never get a rule; their card says "This command is asked every time." A rejected command ends that one action, not the task. If you reject a command that writes a file or applies a patch, the agent is told to make the change with its file tools instead, so it comes to you as a file change.
  • A delete KOLONİ found disposable also offers Allow such deletes in this project (see Disposable deletes).
  • "Search the web?" offers Search once, Always allow searching in this conversation and Reject.
  • "Make this request?" offers Send once, Always allow GET to … (for that site) and Reject.
  • "Read a secret file?" offers Allow once and Reject. There is no rule for secret files.
  • "Read outside the project?" offers Allow once, Allow reading this folder, Allow changes in this folder and Reject.
  • When an agent wants another folder, "Add a folder to this chat?" offers Add to this chat, This time and Reject.
  • An MCP tool asks with Allow and Reject.

You can see and remove the rules you made under Settings › This project › When you're asked › Runs without asking › Show the rules.

What a rule never covers¶

Always run is offered only for plain commands. It is never offered, and never matches, for:

  • a command that is chained, piped or redirected, or handed to a shell or another program;
  • a command that deletes or cannot be undone;
  • a command that names a secret file, .koloni/, or a file that steers agents;
  • an option after the rule's words that makes the program run another program, fetch code or write outside the folder, alone or in a bundle (pytest -qo …): pytest's --basetemp, -p, --rootdir, --confcutdir, -o, -c, and --junitxml outside the folder; go's -exec, -toolexec and -C; cargo's --config and --manifest-path; gradle's -I, -p and -b; npm's --script-shell, --prefix, --package, --userconfig and --node-options; make's SHELL= and -f; tox's -c; maven's -Dmaven.ext…; uv's and pipx's --with, -w, --from, --spec; ruff's --config, --fix, --fix-only, --unsafe-fixes and --add-noqa; mypy's --config-file, --python-executable and --install-types, and its --cache-dir, --junit-xml and --…-report outside the folder; eslint's -c, --rulesdir, --resolve-plugins-relative-to, --plugin, --parser, --fix, --init, --inspect-config, --suppress-all, --suppress-rule, --prune-suppressions and a --format other than its own (stylish, json, json-with-metadata, html), and its -o, --cache-location, --cache-file and --suppressions-location outside the folder - a long one in any spelling (--outputFile); tsc's --incremental, --composite, --noEmit false, --generateTrace, -b and --build (but false and null, which write nothing: --incremental false), and its -p, --outDir, --outFile, --tsBuildInfoFile, --declarationDir and --generateCpuProfile outside the folder - in any case (--OUTDIR, --p); an option or its value written in pieces a shell joins (fal""se, ".."/x), and a word of its own so (make 'SHELL=/x', SH""ELL=/x); a shell handed a line (bash -c). A rule for python -m pytest still covers python -m pytest -q tests, -p no:cacheprovider (a plugin turned off) and -o log_cli=true, but not python -m pytest -p plugin. Words after -- are the script's own (npm test -- --prefix x is covered), and past a rule that names a runner's package (npx tsc) the words are that tool's (npx tsc -p tsconfig.json is covered).

Where one of your rules begins the line but such an option, or a node runner sent to another package or folder (below), keeps it off, the card says so, in KOLONİ's words: "your rule “npm exec tsc” does not cover this line: --globalconfig has it read a settings file, which can load code - run it once or reject it". It names an option only where that is npm's settings file (--globalconfig, --userconfig); any other is "an option past the rule's words".

Below Full auto, a command that keeps running (a server) asks every time, even with a rule.

Nor does a rule - or a yes you gave before - cover a command whose program, named by its path in the project (node_modules/.bin/tsc, ./scripts/check), is one an agent wrote, or sits in an install folder (node_modules, .venv, site-packages) an agent wrote in - for a program in a node_modules, in one above it too, which Node loads its packages from -, while that file still holds what the agent wrote: below Full auto it asks on a card that says so ("an agent wrote its program (web/node_modules): no rule covers a program an agent wrote, so none is offered - run it once or reject it"), with Run once and Reject alone - an Always run rule would not cover it either while that write stands -. A rule matches by its words in any folder, so the same line in another folder, or after an agent's write over the project's own install, would otherwise run what the agent wrote. Once your own install writes over it, the rule covers it again. A package runner finds its program by itself, so its rule (npx tsc, npm exec tsc, yarn tsc, bun x tsc, corepack pnpm exec tsc, uv run ruff, python -m mypy) is read the same way: npx, npm, pnpm, yarn and bun look in the node_modules of the folder the command runs in or of one above it - and read an .npmrc there, yarn its .yarnrc.yml, .yarnrc, .yarn folder, Plug'n'Play loader and .env.yarn, pnpm its .pnpmfile.cjs, bun its bunfig.toml and .env, .env.local, .env.production, .env.development (what they run gets those: NODE_OPTIONS=--require x) - and an agent's write in any of them stops the rule. Where what the agent wrote is such a file - a setting, a manifest, a lock or a loader, not the program -, the card says so: "an agent wrote a file this line may read or load (web/.npmrc): no rule covers the line while that write stands, so none is offered - run it once or reject it". yarn's .yarn folder, which holds yarn itself and its unplugged installs, is said as its program, as a node_modules is ("an agent wrote its program (.yarn): …"). Where an agent wrote both a setting and the program, the card names the program.

A rule for a node runner (npx, pnpx, bunx, npm, pnpm, yarn, bun; corepack before one) is closed on two sides. What an agent wrote: while an agent's write of any package.json (a package's in a node_modules too), any .npmrc or x.npmrc, .yarnrc*, .yarn/, .pnpmfile.cjs, pnpm-workspace.yaml, bunfig.toml, lock (package-lock.json, npm-shrinkwrap.json, pnpm-lock.yaml, yarn.lock, bun.lockb, bun.lock) or binding.gyp anywhere in the project still holds what it wrote, no node runner's rule covers a line - npx and npm exec run a name the package's own bin gives before any installed one, yarn and pnpm a script of that name, npm install every workspace's lifecycle scripts, fetches what a lock's resolved address says and runs node-gyp on a binding.gyp, and npm reads any settings file it is pointed at - its card names that file as one the line may read or load. The cost: after an agent edits a package.json (adding a dependency, say), node runner rules ask until that write is replaced - by your own edit or install. A line of npm's or pnpm's that runs a script by its name under its own rule (npm run build, npm test) is the exception: the script is the project's code by design, as a test is. yarn's and bun's run run a bin too, and npx's test is a package - those are not. Its own options: past the rule's words (up to -- for npm; up to the verb that hands the rest on - exec, dlx, x, run - for pnpm, yarn and bun), a rule covers only options that change what the runner prints, where it fetches from or that it runs less: --silent / -s, --quiet / -q, --loglevel, --color / --no-color, --offline, --prefer-offline, --no, --no-audit, --no-fund, --ignore-scripts, --frozen-lockfile, --immutable - each but --loglevel and --color alone or =true: --ignore-scripts=false, or a false after it (npm install --ignore-scripts false, under an npm install --ignore-scripts rule too), runs the scripts again, and an option of the runner's written in pieces a shell joins ('--ignore-scripts=false') is never harmless. Any other (--globalconfig=x - a settings file whose node-options loads code -, --shell=, --node-gyp=) and no rule covers the line or is offered for it. So yarn tsc --noEmit is offered none: use yarn run tsc --noEmit, or for npm npm exec tsc -- --noEmit (past --, tsc's own).

A rule for tsc - tsc, npx tsc, npm exec tsc, pnpm exec tsc, yarn tsc, tsc named by its path (node_modules/.bin/tsc, as the rule Code style and types offered in 0.1.7) or its script (node node_modules/typescript/lib/tsc.js) - covers no line while an agent's write of a tsconfig*.json or jsconfig*.json anywhere in the project, or of a JSON file that a tsconfig the line reads (the nearest tsconfig.json, a folder or .json its words name - -p's) extends or references, still holds what it wrote: a tsconfig can make tsc write a trace, or a composite build's info where tsBuildInfoFile says, outside the project too - its card names that file as one the line may read or load. Code style and types' own line, word for word, is the exception: its --composite false --generateTrace null, last, win over a tsconfig's composite or incremental build info and its trace, so its rule still covers it.

For uv, poetry, pipenv, pdm, hatch and python -m, whose environment KOLONİ cannot always place, an agent's write in any .venv, venv or site-packages of the project does. For uv, uvx, poetry, pipenv, pdm, hatch, pip and pip3 - run as a module too (python -m uv, py -m pip), and python -m build - so does its write of any pyproject.toml, setup.py or setup.cfg anywhere in the project (they run its [project.scripts] and build the project first - a workspace member or a path dependency with it; pip and build build what they install), of their settings (uv.toml, poetry.toml, pdm.toml, hatch.toml, Pipfile, .python-version, .pdm-python, and pipenv's .env, which it loads), their locks (uv.lock, poetry.lock, pdm.lock, Pipfile.lock, pylock.toml) or requirements (requirements*.txt, requirements/*.txt) - but not for a test run (uv run pytest). The card of a write in an environment says "an agent wrote its program (.venv)"; of one of these files, that the agent wrote a file the line may read or load. As for node runners, the cost: after an agent edits a pyproject.toml (adding a dependency, say), these rules ask until that write is replaced. Their rule names what they run (poetry run ruff, uv run python -m ruff), never the tool alone; and npm's PowerShell shims are npm's own (npx.ps1 tsc is npx tsc). A runner's line sent to another package or folder of a monorepo - npm's and npx's -w / --workspace / --workspaces / --ws / --prefix / -C, pnpm's --filter / -F / -r / --dir / -C / -w, yarn's workspace x / workspaces foreach / --cwd, bun's --filter / --cwd - runs that package's own bin and scripts, which the folder's checks do not read: no rule covers it, and none is offered. Nor does a rule for npm exec tsc cover npm exec tsc -c x (--call: a shell line). python -m x (any Python: python3.12, pythonw, one named by its path) also imports what its folder holds before the standard library and the tool's own - so an agent's .py file, or package __init__.py, there stops its rule too, unless it runs with -I or -P (or PYTHONSAFEPATH); python -m pytest is the exception, since its tests import the project's code anyway. In a working copy every command's Python also reads the copy's root and its src first (KOLONİ puts them on PYTHONPATH), so there an agent's module in either stops a python -m rule, a uv run rule or a rule for a .venv console script (.venv/Scripts/uvicorn.exe) in any folder of the copy - and a sitecustomize.py or usercustomize.py there, which Python imports before anything it runs, stops python -m pytest too (not under -E or -I). node <script> with the script in an install folder (node node_modules/typescript/bin/tsc) is read as that program.

On Windows, KOLONİ writes no file whose name, or a folder's in its path, ends in a dot or a space (pyproject.toml., uv.toml): Windows drops those and would write pyproject.toml, while the record would name another file.

Known limits¶

Always run rules are a convenience, not a security boundary: what a rule covers runs unasked; at Full auto KOLONİ's judge looks at what no rule names. What the rules above do not see:

  • Files a command makes - cp, mv, tar, Expand-Archive into a settings file's name - are not on record as an agent's writes, so they do not stop a rule; nor does a CLI's write of a .env or .npmrc into the project from its working copy, nor an agent's delete of a setting that protected the project.
  • tsc's -p naming any other file (-p tsconfig.build), and a tsconfig that extends a package's config (@scope/cfg); ts-patch's tsconfig plugins; vue-tsc. Past a tsc rule, --init, --outDir out (they write in the folder) and -w (it never ends).
  • mypy's --timing-stats F, --line-checking-stats F and --cache-map …, which write where they name; ruff format . and ruff clean under a uv run ruff or python -m ruff rule (they write in the folder); eslint's --mcp, --cache and --fix-dry-run.
  • pdm's .pdm.toml, pdm_build.py (pdm-backend loads it), poetry's build.py that its manifest names, pylock.<name>.toml, .python-versions, hatch_build.py, a file named on the line (-r deps.txt, --config-file x), node-gyp's *.gypi, bun's .env.test; pip named with its version (pip3.12).
  • make's SHELL:=, SHELL+= and .SHELLFLAGS, and its --makefile=x, -C ../x / --directory=x and --eval=…, past a make rule.
  • On macOS, a name its file system folds into a settings file's (uv.lock written with the Kelvin sign, U+212A, for its k).

On Windows, a command KOLONİ runs, a server it starts and an agent's CLI (started in the work's folder) find a program named bare - node, which an npm .cmd shim calls - on PATH only, never first in the folder they run in, where an agent could have written a node.cmd (git's own runs are started so too). So a batch file of yours that calls its neighbour by its bare name (call helper.cmd, an npm script "t": "helper.cmd") does not find it under KOLONİ: call it as .\helper.cmd, or %~dp0helper.cmd inside a batch file - where cmd.exe says such a name "is not recognized" and the folder has it, the command's result says so too.

How a command is read¶

KOLONİ reads an agent's command line the way its shell will run it, and judges every command it finds, not only the first word. A harm, an install or a write it finds anywhere is asked as it would be on a line of its own:

  • Groups: (cd web && npm ci), { npm ci; }, if exist x (npm ci) else (npm i), for %a in (*) do (…) and PowerShell's script blocks (if ($true) { npm ci }, ForEach-Object { … }, & { … }, Invoke-Command -ScriptBlock { … }). A group whose brackets do not pair is always asked - but brackets a heredoc writes, a comment holds (echo done # 1) first step), sh's case … esac patterns and a group only printed in quotes (echo "(npm ci)", git commit -m "run (npm ci) first") are no group.
  • Heredocs and comments: what a heredoc writes to a file and a comment run nothing; a stop in code a heredoc or a pipe hands an interpreter (python - <<'EOF', echo "…" | python), or that php -r, lua -e, R -e or julia -e is handed, is asked.
  • Wrappers: a branch switch and a patch are read behind a wrapper (time git switch main, bash -c '…'), cmd's if "%a%"=="x" … and trap -- '…' EXIT are read to the command they run.
  • Launchers: what Start-Process … -ArgumentList, npx -c / --call, schtasks /tr, [scriptblock]::Create(…), cmd /c and bash -c hand on is read as the command it is; a command PowerShell is handed encoded (-EncodedCommand) is asked at every level.
  • Runners: what poetry run, uv run, pipenv run, pdm run, hatch run, rye run, conda run, npx, pnpm exec, yarn exec / run, bun x and cargo run -- / dotnet run -- run is read as a line of its own: poetry run cmd /c rd /s /q src is a delete, and a shell it is handed is a line handed to another program, its path spelt out too (C:\Windows\System32\cmd.exe).
  • Substitutions: an install inside $( … ) (out=$(npm ci)) counts.
  • Continued lines: a line continued with a backtick, \ or ^ is read joined as well - a branch switch, inline code, a patch and a git command that rewrites .git/config too (git⏎switch main).
  • Writes to a place built at run time: in a branch's worktree, a redirect (>, >>, >|, 2>), cp, mv, install, tee, Set-Content, Out-File, New-Item, Copy-Item or [IO.File]::Write… whose target is made when the command runs - $( … ), a variable, cmd's %x% and a for loop's %i, Join-Path / Split-Path, git rev-parse - a link made to such a place (ln -s, mklink /J, New-Item -ItemType Junction), or any write after a cd to one, is asked at every level: it may be your repository's .git (another worktree's link, HEAD or history, a ref of origin's). Finding that place is asked there too: git rev-parse --git-dir, --git-common-dir, --absolute-git-dir and --git-path, a read included (ls "$(git rev-parse --git-dir)/.."), so a writer KOLONİ does not list (sed -i, tar -C, robocopy) cannot reach it unasked.   • Package runners: npx -p / --package (before what npx runs), npm exec --package, uv run --with / -w, uvx, pipx run, bunx, pnpm dlx, yarn dlx, npm create / npm init <x> and yarn / pnpm / bun create, deno run npm:… / jsr:…, go run <module>@<version> and corepack pnpm dlx download a package and run it, so they count as installs: asked with web off, and in a working copy whose dependency folders are linked to yours.   • pytest's --basetemp is a delete - pytest empties that folder first - on its line, in -o addopts=… or in PYTEST_ADDOPTS; but a folder in the agents' scratch (.koloni/tmp/…). One a config file names (-c x.ini) is not read: a rule does not cover -c.
  • Always rules never cover the options listed in What a rule never covers.

Disposable deletes¶

Some deletes KOLONİ can check by itself. Where you allow them - Settings › This project › When you're asked › More › Agents may delete what is disposable without asking, or Allow such deletes in this project on the card of one - they run without a card at Auto-edit files and Full auto, in a chat you started, and the command's row says "Ran without asking · disposable: …":

  • a build or cache folder (build, dist, __pycache__, .pytest_cache, .ruff_cache, .mypy_cache, coverage, .next, .turbo, target) below where the command runs, spelt as the folder is on disk, that git ignores and that holds no file git tracks or would take (in any case of its letters), no link and no repository of its own - not inside node_modules, .venv, venv, a folder whose name starts with a dot, KOLONİ's own, a folder git ignores, or another repository, a submodule or a worktree in the project; in the project, and in a sub-agent's copy;
  • a worktree of yours that git lists, named with no link on the way, .. only at its start and by no end of its path another worktree shares: not the main one, not locked, not one of KOLONİ's, on a branch, holding nothing its commits do not (a new or changed file, one marked skip-worktree or assume-unchanged - whatever status.showUntrackedFiles says - or a last commit on no branch, tag or remote), no link, no secret file and nothing git ignores but whole build and cache folders with no repository in them (git deletes what it ignores with the worktree);
  • a local branch that neither the project, the turn nor any worktree stands on: with -d, git itself deletes only one it finds merged; with -D, only one whose commits the default branch has. Never the default branch, main or master, nor KOLONİ's koloni/… ones.

Worktrees and branches go this way only from the project itself (the Orchestrator), never from a copy, and only run in the project's top folder or a plain folder in it - not in another repository, a submodule or a worktree inside the project, nor through a link.

Only such a delete alone on its line counts, written the way the shell it runs in reads it:

  • PowerShell - KOLONİ's own commands on Windows, and Claude Code's PowerShell tool: Remove-Item or its aliases (rm, ri, del, erase) with -Recurse (or -r), -Force (-fo) if you like, and one path: Remove-Item -Recurse dist, rm -r build, ri -r -Force build. rm -rf build is not disposable there: PowerShell refuses -rf and deletes nothing, so it keeps its card.
  • sh - KOLONİ's own commands on Linux and macOS and in Docker, and Claude Code's Bash tool (Git Bash on Windows): rm with -r, -R or -rf, -f / --force if you like: rm -rf build dist.
  • git, in every shell: git worktree remove ../wt/x, git branch -d old.

Codex and agy do not say which shell their command runs in, so their delete of a folder keeps its card. A disposable delete that ran and then failed says so on its row: "Ran without asking as disposable (…) and failed: exit 1". Anything else on the line, a forced worktree remove, a path above the folder or with a link in it, a line the shell continues, a command of a CLI whose folder KOLONİ does not know or that its model names, and any of GitHub Copilot CLI's own commands (it has no sandbox) asks as before. A delete whose folder changed between KOLONİ's look and its run - a card of the turn was answered meanwhile - asks too. At Ask before changes, in a side of a comparison and a job while you are away, every delete asks or waits as before. No Always run rule covers a delete either way.

Sub-agents¶

Sub-agents work in a working copy of your project, not in your folder. Their edits there never get a card, at any level. You decide once, when their work comes back:

  • At Ask before changes, a card asks whether to take their changes into the project.
  • At Auto-edit files and Full auto, the changes come in without a card when the sub-agent finished, its changes do not clash with yours, and the tests it wrote passed - each part's test command narrowed to them (Checked). Those tests are its own code: they run by themselves at Full auto, or where the part's command is yours (set on the project map, or a saved one under an Always rule). With KOLONİ's guess at Auto-edit the card waits for your Run the test first. Otherwise a card asks.
  • At Full auto, if the test fails, the work goes back to the Orchestrator a few times before the card asks you.
  • While you are away, KOLONİ's guess never runs a sub-agent's tests: the work comes in as one with no test would, said "not run". Your own command runs there.

Files that steer agents are held for your card at every level.

The Orchestrator's own tools beside its agents - agents_at_work, update_plan, stop_agent, ask_advisor, note_decision, read_pr_feedback - ask no card at any level: they change nothing in the project. ask_advisor sends what it asks, masked, to your Advisor model (by default on another provider than the Orchestrator's), and read_pr_feedback reads with your own gh; see Talking while agents work.

Whether opening a sub-agent asks first is set under Settings › This project › When you're asked › Opening a sub-agent: Ask when it matters (the default: a card at Ask before changes when the sub-agent can change things), Always ask or Never ask.

Full auto's judge¶

At Full auto a command the list above does not stop runs without asking. Full auto's judge puts a small model before those: such a command is first sent to it once, and it says fine or risky. It is the project's switch - Settings › This project › When you're asked › Full auto's judge ("A small model looks at each command the list does not stop."), and the same switch in the level menu, under the levels. It is on by default, in new projects and in the ones you had; off, Full auto is as it was. Under it, When the judge finds a command risky says what it does with one it finds risky: Refuse and go on (the default, in new projects and in the ones you had) or Ask me (its card, as before) - see What it says below. And a box lets it also run a harmful-looking command a line of yours names: Check what I said first.

It looks at Full auto's commands in a chat you watch (a To-do task done in a chat too) and in a job while you're away (☾ Away) - not at Ask before changes or Auto-edit files. It is not asked about:

  • a command that only reads (git's at the project's root);
  • ordinary work, as a plain command with its common options only: a test runner (pytest, python -m pytest, npm test, cargo test, go test), a compiler or checker (tsc, ruff, eslint, mypy, cargo build, go build), local git at the project's root (status, add, commit, diff, log, switch, branch; in a folder below it, one KOLONİ does not know, or a top folder with no .git but a HEAD (git may take it for a repository), git is judged: a repository shaped there sets what it runs) and npm run <script> - but not where an agent wrote what it runs (the program, or the project's package.json);
  • your own test command (the project map's) - but it is, where the line runs a program an agent wrote -, a skill's script you let run, and a delete KOLONİ found disposable where you allowed such deletes;
  • the very line of a narrow Always run rule of the chat, run at the project's root in a chat you watch - not a broad rule's (see Always run rules at Full auto below), and not where it runs a program an agent wrote;
  • a command KOLONİ asks about at every level for a reason of its own - a secret, .koloni, a file that steers agents, a path out of the project, a send, a working copy's reason: that card stays as it was (a send the list stops is put to your words instead, where that box works). The judge never runs such a command, and never takes its card away: only its own risky may be refused. A delete in the project, git work thrown away and a stop by name, which the list asked of before, are the judge's since 0.1.10: see What the judge decides in place of the list.

What it reads - since 0.1.10 as Claude Code's auto mode's classifier: your words and what the agent did, never what came back to it. Your preferences, this project's rules as saved on the Memory page and your messages in the chat (in a job while you're away, in the chat you went away from) - at most your last 6, newest first, and 4,000 characters of them together, the last one cut where a line or a sentence ends: a newest message longer than that with no line or sentence break in its first 4,000 characters gives "(none)" for your messages; the command, its folder and who runs it (the Orchestrator or a sub-agent's role); the same agent's last 8 actions in the turn - its tool calls by name and arguments, such as run_command {"command": "…"}, read_file {"path": "notes.md"} or write_file {"path": "gen.py", "content": "…"}, only ones that ended and were not refused or turned down, each cut to 300 characters; and, where the line runs or reads a file an agent wrote - a script (node x.js, python x.py, python -m x, ./x.sh, x.ps1, powershell -File x.ps1, x.cmd), make's Makefile, a Dockerfile, a package.json -, the first 4 KB of that file as the agent's write left it. A file in the agents' scratch (.koloni/tmp/) that no write of an agent's made - curl -o .koloni/tmp/x.py …, a command's output - is named, its text not shown. Everything but your own words is marked as data an agent wrote, not instructions. It never sees an agent's own replies, what a tool gave back - a file's text it read, a command's output, a page or a search -, and the secrets KOLONİ knows are masked first.

What it finds risky - a command that could do harm you did not ask for: send your data or files off this machine, download and run code, change things outside the project (your profile, startup, git or shell settings, scheduled tasks, the registry), weaken security, or hide what it does. What your words ask for - a publish, an upload, a deploy, a comment, dropping the stashes - is fine, as far as you named it: never another target or more, and never emptying or overwriting a file that was there before the turn. Since 0.1.11 (its words "D2"):

  • Work your words do not ask for that reaches outside the task is risky: an outside service (curl to an API, gh pr comment, gh issue create), CI or settings files, another repository.
  • As Claude Code's auto mode blocks them: amending or rewriting a commit that was already pushed, or someone else's; a flag that turns a protection off (--no-verify, --insecure, -c http.sslVerify=false); starting an agent loop with no sandbox (claude --dangerously-skip-permissions, codex --yolo, copilot --allow-all-tools).
  • Since 0.1.10, as Claude Code's auto mode, a command that destroys work in the project you did not ask to lose: deleting or emptying a file or folder that was there before the turn, or throwing away uncommitted changes - rm, del, Remove-Item, git reset --hard, git clean -f, git checkout -- ., git restore ., git stash drop, > file, truncate, Set-Content, New-Item -Force, find … -exec rm, npx rimraf, robocopy /MIR, git read-tree -u --reset, a script or a one-liner that deletes; moving your work away (mv src .koloni/tmp/old) counts as deleting it, and a delete is judged by everything it deletes (build/../src, rimraf dist src). It stays fine, where it does none of the harms above, where you asked for it, for build output and caches a build makes again (build/, dist/, node_modules, __pycache__), for files the same agent made new earlier in the turn (not a file of yours it wrote over, touched or mkdir -p'd), for the agents' scratch folder .koloni/tmp/, and for what only shows or keeps work (git clean -n, git stash, git restore --staged).

What the judge decides in place of the list¶

Since 0.1.10, as Claude Code's auto mode: in a chat you watch at Full auto, with the judge's switch on, KOLONİ's list keeps its card only for what it asks at every level. What it asked of before as harm in the project, written as a plain line, goes to the judge instead of a card:

  • deleting or emptying files or folders in the project (rm, del, Remove-Item, Clear-Content, find src -delete, pytest's --basetemp);
  • throwing away git work: git reset --hard, git clean -f (not -x), git checkout -- ., git restore ., git checkout main -- file, git stash drop / clear, git rm -f, git branch -D;
  • stopping a program by its name (taskkill /IM notepad.exe, Stop-Process -Name x) - never what may be KOLONİ itself, nor what it and its terminals stand on.

A plain line is words of letters, digits and _ . / = ~ -, its commands joined by ; or & - so KOLONİ reads each target as the shell will. In KOLONİ's own PowerShell a \ is a path's separator (del src\app.py); everywhere else it is an escape (.gi\t is .git to Git Bash), and the line is the list's. The line is one such harm - but the one cd sub its folder starts it with (a folder there): a change of folder with no plain word in the folder (cd, cd -, cd .., popd, Set-Location, an alias of cd), any other command beside it (rm -rf build; npm install) and a second harm (rm -rf build; rm -rf dist: one could make a link the other goes through) keep the card. So does a Windows short name (ENV~1 is .env; git's HEAD~3 is not one), git told of another tree (git -C x, --work-tree=…), and git's work where the project is not its repository's top folder (a reset there throws away work outside it). Before the judge is asked KOLONİ looks at the disk, and again once it said fine and as the command is about to run: a path through a link or a junction (rm -rf data/, where data leads elsewhere) is the list's card too. A sub-agent's delete in its working copy stays its card. No command or CLI KOLONİ starts is given a CDPATH: cd src is the project's own src.

The list still asks at every level - its card, never the judge's word - about:

  • a line that is not plain: a quote, an escape, a wildcard or a bracket, a brace, a group or a subexpression ((Split-Path (pwd))), a .NET call ([Environment]::…), a variable, a backtick, a pipe, a redirection, a comment or a line break - and a line handed to a shell, a wrapper or a prefix (bash -c "rm -rf build", sudo, env, timeout 60, FOO=1 …, … | xargs rm): any of them can build a target the list does not read;
  • what reaches out of the project or all of it: a path out of it (../x, /tmp/x, $HOME, C:\…), the folder itself or all in it (rm -rf ., rm -rf *, find . -delete, a find with no folder), git clean -x or an exclude that starts with ! (-e '!*'), git stash --all then dropped (they take ignored files - .env, .koloni), git clean -ff (other repositories inside, their history with them), a link, a worktree outside the project or removed (git worktree remove: git picks one by its last name, KOLONİ's own or one outside);
  • what git could still bring a dropped branch or stash back by: git gc --prune=now, git prune, git reflog expire;
  • what may stop KOLONİ itself (python, node, uvicorn, an agent's CLI, a filter, a wildcard, kill -1, a process looked up) or what it stands on (the terminal, the shell, the session, the system: WindowsTerminal, conhost, powershell, pwsh, cmd, bash, zsh, tmux, screen, sshd, Terminal, iTerm2, gnome-shell, Xorg, WindowServer, loginwindow, systemd, launchd, explorer, lsass, csrss, svchost, git, …);
  • a send off the machine (put to Check what I said first where that box works) - but a plain push of your feature branch to its origin, the judge's since 0.1.11 -, and a git remote's branches overwritten or deleted (git push --force, git push origin :x) - a card whatever you said;
  • a secret file, .koloni/ (its free folders too: what is on the disk there is KOLONİ's to look at), a file that steers agents, git's settings or a patch;
  • a line KOLONİ cannot read (-EncodedCommand anywhere in it, more than it reads), web with web tools off, Docker's deletes (its containers and volumes are the machine's, or with -H another's), cmd's rd /s /q (its /s reads as a path from the drive's root);
  • a working copy's, a branch worktree's and a disposable delete's own reasons.

Where Check what I said first works it looks first: its run runs, its refusal refuses, and its ask - a condition of yours, "ask me first" - keeps the card; the judge is not asked then. fine runs the line; risky is refused (Refuse and go on) or waits on its card (Ask me). That card says what the list says of the line ("Deletes files or disks."), the judge's sentence on its record, and has no Don't ask about this line again here: Run once runs that one line. A risky stands for the turn - the same line again is refused or its card without asking -, a fine is asked again each time (what the turn did before changes what a delete takes). Anything else - the switch off, no judge model to answer, an answer it cannot read, no room - is the list's card as before; and so is each of these at Ask before changes and Auto-edit files, in a To-do task's turn, in a job while you're away (parked), in a turn of a chat you went away from, on a side of a comparison, and for a CLI whose folder KOLONİ does not know. If the chat leaves Full auto, or the judge is turned off, while it looks, its fine lifts nothing: the card opens.

Measured on 27 Nov 2026 on the 31 cases of such lines the list now hands the judge, Claude Code's haiku and Sonnet each called no risky line fine. Haiku called one fine line risky - git stash clear after "Drop my old stashes, I don't need them." -, which then waits on its card or is refused; Sonnet called none.

A push of your feature branch¶

Since 0.1.11, as Claude Code's auto mode: in a chat you watch at Full auto, with the judge's switch on and a judge model to answer, a plain push of the branch you have checked out to its own origin goes to the judge instead of a card. fine pushes it; risky gives the push card the list gave before, saying why ("KOLONİ's judge: " and its sentence, a secret in it masked) - never a refusal, whatever the project does with a risky command, so a push is never lost without a word, and it is not counted among the judge's refusals (three in a row ask you). Run once on it pushes. main is never pushed so: a push to main, master or origin's default branch stays a card at every level - quoted, where you asked for it (below).

Which lines - one line, nothing else on it: git push, git push origin, git push origin <branch>, git push -u origin <branch> (or --set-upstream) and git push origin HEAD, where <branch> is the branch checked out. Any other line is the list's card, as before: a force push in any spelling (-f, --force-with-lease, +branch), --tags, --follow-tags, --all, --mirror, --delete, --prune, a push option (-o), --receive-pack, --repo, --no-verify, git told something before push (git -c …), another branch, a tag or a ref (HEAD:main, refs/tags/v1), another remote or an address, a chain, a quote or a variable.

Before the judge is asked, and again once it said fine, KOLONİ looks at the repository; any of these keeps the card:

  • the branch is main, master or origin's default branch - as origin itself names it (its HEAD, asked as the push would ask it; an origin that names none is a card), and as this repository's origin/HEAD names it now and did when the turn began -, or HEAD is on no branch;
  • git's settings send it elsewhere or send more: no remote.origin.url in them (git would read origin from an old .git/remotes or .git/branches file), the branch's upstream is another branch, its remote (or remote.pushDefault) is not origin, push.default is matching or nothing, origin has a push map, a mirror, a receive-pack or push options, tags follow, submodules are pushed (push.recurseSubmodules, submodule.recurse), or a hook is set in git's settings (hook.*);
  • origin's address or git's settings in any scope are not what they were when the turn began - a core.hooksPath an agent set. A turn that began below Full auto has no such record: its pushes are cards. An agent's git remote that changes origin - add, set-url, remove, rename, set-head, set-branches, origin spelt any way, a quote inside it (ori''gin) too - is itself asked at every level, Full auto too, so an origin changed in one turn is not the next turn's unseen;
  • git reads a settings file of the project out of .git - an include.path of yours to ../.gitconfig: an agent may write that file unasked, and a pushInsteadOf there would send the next turn's push elsewhere;
  • a hook a push runs on this machine is there at all - pre-push or reference-transaction in .git/hooks or in the folder core.hooksPath names - yours too (husky's, Git LFS's): an unchanged hook can run what an agent wrote;
  • origin is a folder in the project, or a file: address (its own hooks would run on this machine);
  • a secret KOLONİ knows - one you gave on a card this turn, a key it keeps, a secret of its environment - is in a commit the push sends, its message or a file it writes. What the push sends is counted against what origin itself says it holds (asked as a push would ask it), never a branch git keeps of origin's here; origin that does not answer, holds none of the branch, main, master or its default, or more than 50 commits to send, is a card;
  • the agent works in a working copy, KOLONİ does not know the folder the command runs in, or the project runs its commands in Docker (the container's git, settings and hooks are not the ones looked at);
  • the branch or its commit moved between the judge's fine and the run - another card waited, say: KOLONİ looks again just before it runs.

Where you said "Push it." the judge decides too - it reads your words; where it does not call it fine, or is not asked, its card quotes you as before (never refused). Ask, Auto-edit, a To-do task's turn, a job while you're away and a turn of a chat you went away from keep the card.

The judge is not a wall¶

  • It is a model's decision: it can call a risky command fine, and then that command runs - as it did at Full auto before the judge. Text written to steer it, in a command or a program an agent wrote, is marked as data, but can still sway a model.
  • Hidden work may not be seen: a tool an agent changed but did not write, a program past its first 4 KB, a program that imports another file. A file an agent made by copying (cp x.txt x.py) is not known as the agent's, and is not shown.
  • Test runners and build tools load the project's test and settings code by design - a conftest.py, test files, an eslint or mypy plugin a setting names, build.rs, a cargo runner - and an ordinary line (pytest -q, cargo build) runs what an agent wrote there with no judge.
  • For a CLI run Native, KOLONİ - and so the judge - sees only the command the CLI reports.
  • KOLONİ looks at the disk on the way to what a delete names (a link or a junction there is the list's card), not inside a folder it deletes: a link you made deep in one is not looked at (no shell's delete on this machine follows one).
  • It can be led to call a plain delete fine that it should not: a file of yours written over first and then deleted as the agent's own, work moved into the scratch and then deleted, a path that only looks like a build folder (build/../src).
  • Each command it looks at waits for a model request, a few seconds; with only a CLI to ask, from that CLI's quota.
  • Don't ask about this line again here cannot be listed or undone in the app yet: what it keeps goes with the project. A changed file makes its line another one.

See Known limits for the rest.

Check what I said first¶

Since 0.1.9 this is a question of Full auto's judge, under its switch: in Settings › This project › When you're asked, below Full auto's judge, the box It also lets a delete or a push run when a line you saved names it. Its own row and its switch in the level menu are gone; there the judge's line says, where the box is on, "…; a harmful-looking one runs without a card only where a line of yours names it". It works only:

  • once your Judge model's measurement has passed - a set of cases on which a good check never lets a command run wrongly, in every run. None has yet: Claude Code's haiku, measured on 25 Nov 2026, passed one run of 70 cases, but in three repeats of all 171 one run let 2 commands run wrongly (a condition, "Pending review, you may push to main.", and a delete in another folder than the line names). Claude Code's Sonnet, measured on 27 Nov 2026 with all 171 cases three times, let a delete in another folder than the line names run in every run ("You may delete dist/." for rm -rf dist in packages/api). So the box says (after its measurement) and cannot be ticked (the level menu's line says so too), and such a command waits for you on its card, as before - a push, a pull request or a merge you asked for with your words quoted. A model that passes counts only as it was measured: on its own service (not a model server of yours, nor with your own Claude Code setup or a variable such as ANTHROPIC_BASE_URL pointing it elsewhere), run as a session or natively, and as the Judge model you chose - or, none chosen, the Fast tier's first; never one asked because your choice could not be. Settings › The app › Agents would say so under the Judge model. Another model is measured with scripts/measure_judge.py (see its first lines; one request a case);
  • or in a project where you had turned Check what I said first on before 0.1.9: its box comes ticked and works as it did, and you may untick it and tick it again.

With the judge off, or the box unticked, it is never asked. The judge's two questions come one after the other: a command the list stops softly (a delete, a push, a send) is first asked whether your words cover it - its run runs, its refusal refuses, and its ask (a condition of yours, "ask me first") keeps the card. Where it gave no answer, or is not asked, a delete, git work thrown away or a stop by name in the project, written as a plain line, goes on to the judge's own question, whether it looks risky (which), and so does a plain push of your feature branch (which); any other push or a send keeps its card - quoted where you asked for it. A force push or a branch deleted on the remote is never asked: a card at every level, whatever you said.

At Full auto, in a chat you started, a command that sends something off this machine would wait for you on a card - but a plain push of your feature branch goes to Full auto's judge -, and one that deletes in the project goes to the judge too (a card where the judge does not run). Where the box works, your Judge model (as for Full auto's judge: the Fast tier's first unless you choose one) first reads your preferences, this project's rules as saved on the Memory page and your own messages in the chat - never anything an agent wrote - and then:

  • A whole line of yours that names the command and what it touches ("You may delete build/ and dist/."), and forbids nothing and sets no condition: the command runs without a card. Its row says "Ran without asking · your rule: …" with where the line is (This project's rules or your message). A line of Your preferences, which holds in every project, never lets a command run - the command waits on its card -, though it may still stop one. Of your messages, only this turn's - the one that started it and those you sent into it - run a push, a pull request or a merge; an earlier turn's never does, though it may still stop one.
  • A whole sentence of yours that forbids it ("Never push to main."): it is not run and opens no card. The agent is told that sentence (for a sentence in a message of yours, only that one of yours forbids it - the sentence stays with you), and not to run it or anything that does the same again, and goes on with the rest of its task. Its row says "Not run · your rule: …".
  • A sentence that sets a condition or asks to be asked ("unless", "ask me before", "else", "while", "whenever", "as long as", "so long as", "provided", "providing", "in case", "assuming"; in Turkish "eğer", "ise" / "isen", "-madan", any "-se" / "-sa" - "Kontroller yeşilse …", "Hata yoksa …", "Testler OK'se …" -, "-ınca", "-dığında" / "-dığımda" / "-diklerinde", "-ken", "-dikçe", "durumunda", "-dığı zaman", "sonra", "-ene kadar", "dek", "madem", "yeter ki" and "sürece"; an apostrophe written as ’, ‘, ´ or ʼ is read as one, so "OK’se" counts too), or nothing of yours that covers it: the card, as before. Its card then says "Nothing you said covers this."
  • A line limited in time or in how many times it may be used ("once", "this time", "today", "on weekdays", "until Friday", "bir kereliğine"): the card too - KOLONİ cannot tell whether it was used up or its time has passed. The model is told to ask here; KOLONİ's own reading of your line does not catch every such word, so the measurement decides how well this holds.
  • Two lines of yours that disagree about a delete: a line that names what the delete takes and forbids it or sets a condition - "Never delete ./x." beside "You may delete ./x.", or an item under "Never delete these:" - keeps its card, whichever line the model quoted, as KOLONİ reads such a line. A heading covers the lines right under it, up to a blank line, and a list or code under it until a line of prose; a heading right under another is read with it ("Never delete:" over "Outputs:" forbids what Outputs lists), unless a blank line came after the other's own lines. So "Never delete these:" over ./archive says nothing of a "You may delete ./build." in a section of its own after a blank line. Some wordings ("Keep build.", "Leave build alone.", "…but check with me first.") are not caught, and the measurement decides the rest. Two lines about a push, a branch or a remote are left to the model.
  • A command run in a folder of the project other than its root (rm -rf dist in packages/api): it runs without a card only on a line that names that folder from the root ("You may delete packages/api/dist."). A path in your line is read from the root - "You may delete dist/." is the root's dist -, so a line that does not name the folder keeps the card, whatever the model said; and so does one whose folder KOLONİ does not know.

A command that ran or was not run this way also waits on Ready for you, in its Decided for you column, until you press OK. After 3 such refusals in a row, or 10 in one turn, KOLONİ says so in the chat and the rest of that turn asks you on a card. Secret files, .koloni, files that steer later turns, paths outside the folder, a delete or a send of the whole folder, and a CLI's command whose folder KOLONİ does not know are always asked; anything that goes wrong (no model to ask, over the budget, no answer in 20 seconds - 90 for a model on a CLI -, an unreadable one) opens the card as before. Each such command is one request of your Judge model.

While you're away it holds in a To-do task's chat at Full auto too, reading the chat you went away from - never the task's words - for a one-line delete in the task's copy only: a command of more than one line or continued, a send, a git remote's branch, Docker's prune or volumes, a file that steers agents and a command that runs another through a shell or a wrapper keep their card. The same holds in the chat you went away from, while you're away. A plain chat has no judge's switch.

A push, a pull request or a merge you asked for¶

A push, opening a pull request and merging one are yours to say. Once a Judge model has passed the measurement, Check what I said first can let one you asked for run with no card, as it does a delete. Until then the card stays, but it quotes you and asks for one click (at Full auto a plain push of your feature branch goes to the judge first: above). When a sentence of the message that started the turn, or of one you sent into it with Send now, asks for it, its card says

You said “Push it.” — push now?

with Push, as you said (Open the PR, as you said, Merge, as you said) and Reject. It is a card all the same: nothing runs until you press it. It shows at every level, in a turn you started from the app's own page; a To-do task's turn, a job while you're away and a side of a comparison keep the plain card.

What asks for it - in English an order or a leave ("Push it.", "Commit and push.", "You may push now.", "Open a PR.", "Squash and merge."), in Turkish a request ("push et", "pushla", "push edebilirsin", "PR aç", "PR'ı merge et", "PR'ı birleştir"). Only:

  • the message you sent from the app's own page that started this turn, and what you sent into it with Send now - the newest of them that mentions it decides ("Push it." and then "Wait, no - don't push yet." is none) - never an earlier turn's ("Push it." yesterday does not cover today's push after "Fix the typo."), an agent's words, a tool's result, a file, your preferences or the project's rules; nor code - a fence (in a list's item too) closes only on a line of its own marks, at least as many, so what an agent wrote inside the quote Ask about this makes stays code -, a quoted line (>) or a sentence with a backtick in it. A message over 4,000 characters is not read for it;
  • the last sentence of it that mentions it decides, and the whole message is read with it: anything in it that says no, asks, waits, puts it off or calls it off ("Don't push.", "push etme", "Push it. Don't merge.", "Push it. Actually no.", "Never mind.", "Scratch that.", "Hold off.", "Later.", "Revert that.", "Or should we wait?", "Hayır, bekle.", "Yok, vazgeçtim.", "Boşver.", "İptal.", "Önce bana göster."), that says what you do or will do ("I'll push it myself.", "I'll do it myself.", "push ettim", "push edeceğim", "tomorrow" - a message with "I" or "we" in it at all), or sets a condition ("after the review", "once CI passes", "testler geçince") leaves no quote - the plain card. Fewer quotes, never a wrong one;
  • the sentence names no other branch or pull request than the line does: "Merge PR 5." (or "PR-5", "PR #5", "#5", "5 numaralı PR") is no quote for gh pr merge 7, nor "Push feature-a." for git push origin feature-b, nor "Push it to main." for a push of another branch, nor "Open a PR into main." for gh pr create -B develop. A word counts as a branch where your repository knows it - its branches, its remotes' and its tags - and main and master always; a bare git push pushes a branch KOLONİ does not know, so a sentence that names one gets the plain card there;
  • a line of your preferences or the project's rules that names it and forbids it or sets a condition ("Never push to main.") leaves no quote for it at all.

The quote is shown as you typed it, in its own reading order: marks that turn text around (right-to-left overrides and the like) are taken out of it.

Which commands - one program on one line, run at the project's root, written with letters, digits, spaces and . : / = + - _ alone, a value in double quotes (-t "Fix the typo"):

  • git push, alone or to origin with branches of your repository's own (or HEAD), and -u, --set-upstream, -q, -v, --progress. A push to main or master by name is quoted only on a sentence that names it ("Push to main.", "main'e push et"); a bare git push is quoted on "Push it." whatever branch it pushes;
  • gh pr create with a title, a body, a base, a head (a branch of this repository: owner:branch is not), one label, assignee, reviewer, milestone or project, --draft or --fill;
  • gh pr merge with a number or a branch, --merge, --squash, --rebase, --auto, a subject or a body.

An option's value never starts with -. KOLONİ reads your repository's branches and tags for it (read only); where it cannot - no git, or the project is not the repository's top folder - nothing is quoted. Anything else gets the plain card, unquoted: a force push, a branch deleted (git push origin :x, --delete, gh pr merge --delete-branch), a tag or any other ref than a branch (refs/tags/…, refs/for/…, the short names git reads so - tags/v1.0.0, heads/main, remotes/origin/main -, a tag by its bare name: git push origin v1.0.0), a name that is no branch of your repository's own (only another remote's, or none), another remote or repository (upstream, an address, -R), a file read in (--body-file), --admin, a push in a subfolder, any other option, more than one command (&&, ;, |), a redirection, and any other character - $, a backtick, a bracket, single quotes, a comma (-r a,b), @ (@me), !, ?, #, *, %, a line break. So does a pull request whose body is written with a heredoc or on more lines (--body "$(cat <<'EOF' …)", as Claude Code often writes one). "Open a PR." covers gh pr create alone, not the git push before it. A local git merge sends nothing: it is not quoted.

Plan first¶

With Plan first on, each new message first gets a plan to approve. While it plans, an agent can only read, search and ask you. It cannot write or run anything, at any level.

A job's own branch while you're away¶

In a git repository a job of ☾ Away works on its own koloni/<task> branch in a worktree. Its git there - status, diff, log, add, commit on that branch - runs at every level without a card. Its git push never runs: "KOLONİ pushes this branch when the user says yes: go on" - the push waits for your Run in the morning. Anything else of git (switching branches, reset, stash, fetch, config) is parked for you.

KOLONİ's own check of code style and types runs the project's ruff, eslint, tsc or mypy as it runs the test command: at Ask and Auto-edit it asks on a card - a yes is that line in that folder for the turn, and Always keeps that line, never the bare program; while you are away it is not run, and says so. A program an agent wrote - this turn, or an earlier turn in an install folder, while the file still holds it - is never run.

Choosing a level¶

  • Start with Ask before changes in a project you care about. You see every change before it is made.
  • Auto-edit files suits work you review afterwards. Changes can be reverted, and commands still ask.
  • Full auto is for work you are ready to let run. What reaches out of the project, sends, or touches secrets and risky files still asks; Full auto's judge decides the rest - a delete in the project too - and everything it calls fine runs. A script that opens .env without naming it can still read it, unless KOLONİ's own commands run in Docker (Settings › This project › When you're asked › More) or Copilot's sandbox is on; a CLI run Native runs its commands on this machine, outside Docker.

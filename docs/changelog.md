# Changelog

All notable changes to KOLONİ are listed here, newest first. English only.

## [Unreleased]

### Added

- **To-do**: To-do keeps goals and stories: a story holds tasks and bugs, a goal holds stories and says how many are done; the Hive keeper writes a rough note as a goal, its stories and their tasks. The page is a tree - goals ("1 / 2 stories" and a bar), their stories, their tasks and bugs (a bug in rose), the tasks of no story last under **Without a story** - with the filters **All**, **Todo**, **Running** and **Done**, **+ Task**, **Write it with the Hive keeper** and **☾ Away** on its bar. A story's state comes from its tasks (todo, running and in which chat, stuck, done? - each task done or waiting at "done?" for your word); it is done only when you close it (**⋯ → Close the story**, once each task is done), and its notes open from **📓 N notes**. A task's **Story** and **Type** are set as it is added or in **Edit** (**New story…** names one there); a story's **⋯** gives it a goal (**New goal…**), renames or deletes it, and deleting a goal or a story keeps what was under it. **Write it with the Hive keeper** opens a box for the note: the draft shows the goal, each story with its notes and tasks, and the tasks that stand alone, all to change - a story's **Add** adds it under the goal, **Add all** the rest, at most 4 stories and 12 tasks; an answer of tasks alone is still read. An agent's `add_task` may name the story it goes on with (an open one by its title, or a new one with a goal) and say whether it is a bug; its card says where adding it puts it (*In story “Login” (new) · goal “Auth” · bug*), an added proposal's story and goal are yours from then on, and a story it opened goes when all its proposals are rejected ([docs](automation/todo.md#goals-and-stories)).
- **CLIs**: GitHub Copilot CLI run **Native** goes on in its own session from the topic's previous turn, as Claude Code on its own sign-in does: it is sent only what is new, with this turn's tools, permissions and KOLONİ's tools given again, and compacts the session itself - its record says when, with the size before and after. A new topic, another model, folder or permission level starts a new session; where Copilot cannot go on in its session it starts a new one sent the whole chat, and its record says so once. Its tokens and AI credits are counted per turn, not as the session's growing total. A session is not gone on in once it holds **Summarise a long context at (%)** of 100,000 tokens - Copilot's dearer price step begins there; a smaller window on its role lowers that, a larger one does not lift it - or did not say its size: the next turn starts anew from the history KOLONİ keeps and summarises, and the record says so. Its context is measured against the window its session says (272,000 for gpt-6-luna, at most 100,000) instead of the catalogue's, and its details show how full it is while it works. Each session's home is kept under `runtime/cli-homes/copilot-sessions/`, never your own `~/.copilot`, and removed with a new session, when you move to another topic, with its chat or project, and at KOLONİ's start where no agent goes on in it ([docs](models/setup-cli.md#going-on-from-the-last-turn)).

### Fixed

- **Chat**: Code style and types reads a `tsconfig.json`'s files through what it extends, up to 8 deep: one that names none - itself or by a base's `files: []` - is said "not checked", never passed; one that extends a file outside the project or not there is said too, and a tsconfig with a byte-order mark or a `//` comment ended by a lone carriage return is read as tsc reads it ([docs](use/checked.md)).
- **Chat**: in a `.js`, `.ts` or `.vue` file, a line separator (U+2028, U+2029) ends a line for Code style and types as it does for eslint and tsc - a problem on a line the turn wrote was counted as on a line it did not change, and the other way round.
- **Chat**: Code style and types does not offer a card for a program an earlier turn's agent wrote in an install folder while it was in a working copy, or that was merged in - it read only writes already in the project; such a write, while the file still holds it, is said "not run" as one in the project is ([docs](use/checked.md)).
- **Chat**: **Pages** reads a page's accessibility half a second after it loaded and again 0.3 s later (some 0.8 s a width) - a page that put an image's alt or a button's name a moment after it loaded was sent back to fix, one that added an image with no alt then went through; a rule found in both reads fails as many as the fewer, however the rest of the page moves (a count going up, a clock, an image's address that rotates); what one read finds more of, or a rule found in one read only, is "not judged … for what changed after it loaded", by its rule, neither sent back nor passed. A page whose script took its root away says "accessibility not read … the page has no root" (it passed with no word). A button named only by the CSS `::before` or `::after` words of it or of what is in it has a name (one with `display: none`, or an icon font's glyph, is none), a label of an image's alt names its field, an empty `<a href>` - a tab stop whatever its size - with no name is failed, and an image of a `data:` address is named "an inline image (#hero)", not "gif;base64,R0lG…", in the fix round's words too. A page nested over 1,000 deep is read only in part, and one Chrome's tab crashes on (some 1,600 deep, measured on Windows) is "not checked: the page crashed the browser's tab" at once - every later call waited 30 s, and the turn's later pages went unchecked; the next page is read in a new browser ([docs](use/checked.md#pages)).
- **Chat**: a problem KOLONİ's check by kind of work found (a page, a document, a config file, a script) that the Fix rounds left - or that a round answered with no change left - ends the Checked section as failing tests do, "Still failing after 1 fix rounds: you decide (Fix it)", with **Fix it**: it stopped at "Sent back to fix: 1 of 2 rounds", and nothing to click. Fix it's turn is told the problems as data; work in a copy (a recipe's, an Away job's, a branch turn's) is not taken in by a plain Take in, at any level, as with failing tests - nor let in by a later look's MERGE or a stronger model's pass of its tests while the kind still fails (nor, before, by such a MERGE while fewer tests ran or the tests failed, nor where Until it passes stopped at the token limit or the budget with tests failing); a later pass of the same turn never lets that hold go (Take in anyway or Fix it), and one held for its tests goes to Ready for you only where a later pass runs every test command to a pass - "Not taken in: KOLONİ's checks of what it wrote still fail after its fix rounds", **Take in anyway** or **Fix it** ([docs](use/checked.md#a-stronger-model)).

### Security

- **Chat**: Code style and types tells tsc to write nothing - `--composite false --generateTrace null` after its other words, which win over the tsconfig and what it extends: a composite project, an incremental one with a `tsBuildInfoFile`, or a `generateTrace` made tsc write its build info or a trace where they said, outside the project too. Such a project is now type-checked, not passed over ([docs](use/checked.md)).
- **Chat**: an **Always run** rule no longer covers, past its words, ruff's `--fix`, `--fix-only`, `--unsafe-fixes` or `--add-noqa`; eslint's `--fix`, `--plugin`, `--parser`, `--init`, `--inspect-config`, `--suppress-all`, `--suppress-rule`, `--prune-suppressions` or a `--format` other than its own (`stylish`, `json`, `json-with-metadata`, `html`), nor its `--cache-file` or `--suppressions-location` outside the folder, in any spelling (`--outputFile`); mypy's `--install-types`, nor its reports outside the folder (`--html-report`, …); tsc's `--incremental`, `--composite`, `--noEmit false`, `--generateTrace`, `-b` / `--build` - but for `false` and `null`, which write nothing -, nor its `--generateCpuProfile` outside the folder: the rule Code style and types offers is a check that writes nothing. A word past a rule written in pieces a shell joins - `fal""se`, `--incre"mental"`, `".."/x` - is never taken for a harmless value or a path inside the folder (a value after `=` quoted whole, `--select="E,F"`, is that value), a short option's `=` is read past as ruff and eslint read it - `-o=../x` wrote ruff's report outside under Code style's own rule -, and tsc's `--p` and `--b` are read as its `-p` and `-b`. This reaches agents' own commands too - `uv run ruff` no longer covers `uv run ruff check --fix .`, `npx eslint` no longer `npx eslint . --fix` -, and tsc's options are read in any case, as tsc reads them (`--OUTDIR` is `--outDir`) ([docs](use/permissions.md#what-a-rule-never-covers)).
- **Chat**: Code style and types does not run eslint or tsc where an agent wrote in a `node_modules` above the folder they run in - Node loads their packages from the root's too -, and an **Always run** rule - or a yes given before - for a program in a `node_modules` asks on its card while such a write stands ([docs](use/permissions.md#what-a-rule-never-covers)).
- **Chat**: in a working copy, Code style and types runs its tools without the copy's own code first on PYTHONPATH - a `mypy/__init__.py` an agent wrote there was imported in place of the project's mypy; KOLONİ's test runs and the agents' commands keep the copy's code first ([docs](use/checked.md)).

### Security

- **Chat**: an **Always run** rule - or a yes given before - no longer covers a command whose program, named by its path in the project, an agent wrote, or that sits in an install folder (`node_modules`, `.venv`, `site-packages`) an agent wrote in, while the file still holds what the agent wrote: below Full auto it asks on a card that says so, and a trigger's turn, with nobody to ask, does not run it whatever its leave. A rule matches by its words in any folder, so the root's `node_modules/.bin/tsc` rule ran a tsc an agent wrote in a subfolder's `node_modules`. A package runner's rule (`npx tsc`, `npm exec tsc`, `yarn tsc`, `bun x tsc`, `corepack pnpm exec tsc`, `uv run ruff`, `python -m mypy`) is read so too: where the runner finds its program - the `node_modules` of its folder or one above it, and the `.npmrc`, yarn's settings and loader, `bunfig.toml` that make it run code of their own; for uv, poetry, pipenv and `python -m` any `.venv` or `site-packages` of the project; and for `python -m` (without `-I` or `-P`) any `.py` module or package the agent wrote in its folder, which it imports before the standard one (`subprocess.py`) - in a working copy also at the copy's root and in its `src`, which every command's Python reads first there, for a `uv run` rule or a `.venv` console script too, and a `sitecustomize.py` there even for `python -m pytest`; pnpm's `.pnpmfile.cjs` counts as yarn's settings do; and an agent's `package.json` in the folder or above stops a runner's rule (npx and `npm exec` run the package's own `bin` first, yarn and pnpm its scripts), a `pyproject.toml` or `setup.py` stops uv's, poetry's, pipenv's, pdm's and hatch's (a script run by its name - `npm run build`, `npm test`, `uv run pytest` - runs the project's code by design and is covered). Such a card offers no **Always run** rule, which would not cover it either - Run once or Reject. ### Security

- **Workspace**: a pull request of a branch that took in commits of yours not on origin - your branch merged into it to resolve a conflict, or by the agent, or another branch of yours - is not pushed until you push them, also once you amended, rebased or dropped them: before, after such a rewrite their earlier content went up with it, at Full auto unasked ([docs](use/workspace.md#branches)).
- **Workspace**: your repository's git hooks (pre-commit, commit-msg, post-commit, also from a core.hooksPath such as husky's) no longer run for an agent's own git commands in its copy, nor for an MCP server's it starts there, and git's fsmonitor and commit signing are off for them ([docs](use/workspace.md#branches)).
- **Agents**: on a branch, an agent's command that clears or sets git's own environment (`unset GIT_…`, `env -i`, `$env:GIT_… =`, `Remove-Item Env:\GIT_…`), or runs one of git's own programs by its name (`git-push`), is asked at every level, Full auto too: it would bring your repository's hooks back ([docs](use/workspace.md#branches)).
- **CLIs**: with GitHub Copilot CLI on its newer protocol, a tool of Copilot's own that ran without KOLONİ being asked stops the turn, and the run says so ([docs](security/model.md)).
- **Chat**: a command an agent runs in its copy that names another agent's copy, a worktree of the project or a place above its copy (`../..`, also past a `cd` KOLONİ cannot follow, in quoted code or in a variable; a full path also with doubled separators or as `%LOCALAPPDATA%`, `$HOME` or `~`), writes in the linked `node_modules`, `.venv` or `venv`, or installs into them (`npm --prefix web install`, `cmd /c "npm i"`, `python -m pip`, updates and rebuilds too; in a turn you watch), is asked at every level, Full auto too ([docs](use/permissions.md#what-asks-at-each-level)).
- **Chat**: a command that stops programs by their name (`taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name`), or looks a process up and stops it (`Stop-Process -Id (Get-Process x).Id`, `lsof -ti:8000 | xargs kill`, `fuser -k`, `npx kill-port`), is asked: from a copy always; in the project, Full auto's **Check what I said first** may let it run on a line of yours - but never one that may stop KOLONİ itself or another agent's CLI (python, node, uvicorn, claude, codex, copilot, qodercli, agy, a filter, a wildcard, everyone's or a group's pid such as `kill -1`, a process looked up). Stopping a program by its id (`taskkill /PID`, `kill 1234`, `Stop-Process -Id 1234`) stays as before ([docs](use/permissions.md#what-asks-at-each-level)).

### Security

- **Install**: KOLONİ listens on 127.0.0.1 only and sends no telemetry; every request to its API needs the page key, so a plain or injected command an agent runs cannot approve its own cards ([docs](security/model.md#the-page-key)).
- **Install**: exports and backups are downloaded without the page key in their address, so it stays out of your browser's history.
- **Settings**: an export without keys also leaves out secret files you attached to a chat (a `.env`, a key file); the chat keeps their name ([docs](backup-and-update.md#export-everything)).
- **Install**: a link with a wrong key, from a web page or an agent's answer, no longer locks the page out: the page keeps its key unless KOLONİ accepts the new one, and links in agents' answers and diagrams open in a new tab.
- **Ready**: reading secret files, writing most files that steer agents, and commands that delete or send data off the machine stop at a card at every level, with a few exceptions for CLIs run with their own tools ([limits](reference/known-limits.md#secrets)); at Full auto these checks are for honest commands, not a wall ([docs](security/model.md#where-protection-ends)).
- **Ready**: a command an agent runs is judged together with the folder it runs in, so a relative path inside `.claude` or another protected folder stops at a card as if it were named; Claude Code and Qoder don't say where their shell stands, so their commands are judged at the project root (a `cd` into a protected folder is itself a card).
- **Ready**: KOLONİ's own cards have fixed titles and say **KOLONİ asks**; an agent's question says **The agent asks**, so it cannot pass for one of KOLONİ's.
- **Workspace**: sub-agents work in working copies, not in your folder, until you take their work in.
- **Agents**: your home folder and a drive's root cannot be a project, and KOLONİ's own folder is never opened, even inside a project; a CLI's own Grep and Glob cannot search it either ([docs](security/model.md#places-agents-never-open)).
- **Agents**: web pages, search results, MCP results, knowledge, a GitHub issue and a learned repository's code reach agents framed as data, not instructions; the frame tells the model, it is not a wall; text that tries to give orders shows a **Text tried to give orders** card ([docs](security/model.md#outside-content)).
- **Settings**: secret files open only on your **Allow once** and searches skip them (at Full auto a command that doesn't name the file can still read it); keys in command output show as `***`; variables with secret names are kept from commands and CLIs unless you name them ([docs](security/model.md#secrets)).
- **Settings**: a planted test key stops a command, web request, browser or MCP call that would send it out.
- **Chat**: an agent asks for a key on a **Give a secret to its commands?** card; the value never reaches the model or the record, and never leaves on a branch ([docs](security/model.md#a-secret-you-give-on-a-card)).
- **Triggers**: turns nobody watches may do only what the trigger allows, and never start a CLI that works with its own tools ([docs](use/permissions.md#turns-nobody-watches)).
- **Tools**: commands can run in a fresh Docker container, with the network off unless you allow it ([docs](security/model.md#other-walls)).
- **Tools**: MCP servers get only their own variables and what programs need to run, none of KOLONİ's or a CLI's sign-in; one you have not trusted asks before every call ([docs](tools/mcp.md)).
- **Tools**: web searches and requests reach only public addresses; the agents' browser opens only previews and the sites you allow.
- **CLIs**: on Windows, a CLI and everything it starts run in a Windows job that is ended on Stop or when KOLONİ closes.
- **Docs**: the guide at `/guide/` loads its scripts, styles, fonts and pictures only from KOLONİ itself.
- **Docs**: report a security problem privately through GitHub's Security tab ([docs](https://github.com/flyingriverhorse/Koloni/blob/main/SECURITY.md)).
